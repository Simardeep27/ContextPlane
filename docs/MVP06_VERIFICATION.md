# MVP-06 verification

Observed September 26, 2026. Acceptance remains with the milestone owner; this
record verifies the isolated implementation, not a hosted deployment or the
shared API/MCP write path.

## Live evidence

[Checked-in sanitized manifest](evidence/mvp06-openrouter-live.json) records the
clean source commit, provider generation IDs, returned model, usage and latency.
It was generated by `packages/e2e/src/live-worker.ts` with a real OpenRouter key
loaded privately into memory and passed to the child environment.

The model proposed/checked a stale revision, received its blocker, requested
coordination, staged and tested the exact corrected candidate, and requested
publication. Billing dependency setup and acknowledgement were deterministic
host actions. SIGKILL happened after publication and before its terminal receipt.
Restart resumed the same saved model job and reconciled that publication.

## Numbers observed

- Final live run: 8 OpenRouter calls, returned model `openai/gpt-4.1-mini`.
- Exactly 2 publications: dependency fixture and corrected candidate. Exactly 1
  corrected publication after actual SIGKILL/restart; no stale publication.
- Corrected candidate: `sha256:6bfefc738caabc24e0b1b0028fb8a24f1e084d6e72e5f245b9f60ba19daa28ea`.
- Focused gateway suite: 20 tests passed, including 6 worker/provider tests.
- Earlier iterations exposed 2 HTTP 404 failures from unsupported provider
  parameters, then a repeated-call loop that exhausted its 8-turn job budget.
  The provider parameters and durable assistant/tool conversation were corrected.
  Failed attempts remain in private isolated test directories; they are not
  counted as successful workflow evidence.

## Regression coverage

Worker tests cover durable inference/tool replay, scoped role tools, invalid tool
arguments, captured-response reconciliation, ambiguous-response fail-stop,
stale-generation commit rejection, lease renewal during slow inference, usage
parsing, hidden-reasoning exclusion and no automatic provider retry. Existing
runner, gateway publication recovery and MVP-07 lifecycle tests remain in place.

Use `npm test` and `npm run typecheck` for the ordinary suite. The live acceptance
run is explicitly opted in via `npm run worker:live`, documented in
[MVP06_WORKER.md](MVP06_WORKER.md). Provider calls are not mocked in the checked-in
manifest; unit-test providers are mocks and serve only regression coverage.

## Remaining limitations

The executor accepts fixed synthetic candidates and registered consumer checks.
Persistence for the live run is the existing single-process file test adapter,
not proof of Atlas transactions or multi-process file locking. The model response
journal requires durable placement beside the run; lost provider responses stop
for operator reconciliation. No exactly-once provider billing, hosted worker,
shared-write integration, autonomous Billing agent or productivity gain is claimed.

Team synchronization is separately blocked in this chat: native `send_message`,
`publish_surface`, and cross-chat messaging returned “MCP tool call requires
approval, but approval policy is never.” Registration, context and inbox reads
succeeded. Sanitized reports are retained privately in `.artifacts/context-sync/`;
this work must not be called globally synchronized until those writes succeed.
